# Contribuindo para SynPhytica

Obrigado pelo seu interesse em contribuir para o SynPhytica! Este documento fornece diretrizes para contribuições.

## 🤝 Como Contribuir

### Reportando Bugs

Se você encontrar um bug, por favor abra uma issue com:
- Descrição clara do problema
- Passos para reproduzir
- Comportamento esperado vs. observado
- Ambiente (OS, Python version, etc.)

### Sugerindo Melhorias

Sugestões são bem-vindas! Por favor inclua:
- Descrição clara da melhoria
- Justificativa (por que seria útil)
- Exemplos de uso, se aplicável

### Pull Requests

1. **Fork** o repositório
2. **Crie um branch** para sua feature (`git checkout -b feature/AmazingFeature`)
3. **Commit** suas mudanças (`git commit -m 'Add some AmazingFeature'`)
4. **Push** para o branch (`git push origin feature/AmazingFeature`)
5. **Abra um Pull Request**

#### Checklist para PR

- [ ] Código segue o estilo do projeto (PEP 8 para Python)
- [ ] Testes adicionados/atualizados
- [ ] Documentação atualizada
- [ ] Commit messages são descritivas
- [ ] Sem conflitos com `main`

## 📝 Padrões de Código

### Python

- Seguir PEP 8
- Docstrings para todas as funções/classes públicas
- Type hints quando possível
- Máximo de 100 caracteres por linha

### Commits

Formato: `<tipo>: <descrição>`

Tipos:
- `feat`: Nova feature
- `fix`: Correção de bug
- `docs`: Mudanças na documentação
- `style`: Formatação, sem mudança de código
- `refactor`: Refatoração de código
- `test`: Adição/correção de testes
- `chore`: Manutenção geral

Exemplo: `feat: add support for TCM compound library`

## 🧪 Testes

Execute os testes antes de submeter PR:

```bash
pytest tests/
```

## 📚 Documentação

Atualize a documentação relevante:
- README.md para mudanças de alto nível
- Docstrings para mudanças de API
- docs/ para documentação técnica
